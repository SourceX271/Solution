# 国际化（i18n）

全站两种语言：`zh`（默认，无前缀）/ `en`（`/en` 前缀）。任何**用户可见文案**都必须走 next-intl，
且中英词条必须逐键对齐——`npm run i18n:check` 在 CI 或提交前强制校验（AGENTS.md 的硬性约定）。

---

## 一、接线全链路

| 环节 | 位置 | 要点 |
|---|---|---|
| 构建插件 | `next.config.mjs` | `createNextIntlPlugin()`（不传参 → 自动探测到 `src/i18n/request.ts`） |
| 路由定义 | `src/i18n/routing.ts` | `defineRouting({ locales: ["zh","en"], defaultLocale: "zh", localePrefix: "as-needed", localeDetection: true })`；导出 `Link` / `redirect` / `useRouter` / `usePathname` / `getPathname` |
| 词条装载 | `src/i18n/request.ts` | `getRequestConfig` → 非法/缺失 locale 回落 `zh` → 动态 `import("../../messages/<locale>.json")` |
| 中间件 | `src/middleware.ts` | `createMiddleware(routing)` 包在 NextAuth 的 `auth()` 里；matcher 排除了 `/api`、静态资源、`uploads`、`favicon.ico` |
| 客户端 Provider | `src/app/[locale]/layout.tsx` | `NextIntlClientProvider messages={await getMessages()}` |
| 服务端文案 | 各 RSC 页面 | `getTranslations(namespace)` / `getLocale()` |
| 客户端文案 | 各 `"use client"` 组件 | `useTranslations(namespace)` / `useLocale()` |
| 元数据 | 根 layout + `[locale]/layout.tsx` | 根 layout 只能给中文兜底；`[locale]` 层用 `common` 词条按语言覆盖站点名/描述/关键词/OG |
| `<html lang>` | `src/components/HtmlLang.tsx` | 根 layout 无法得知 locale，故由客户端组件在挂载后同步 |
| API 文案 | `src/lib/api-i18n.ts` | API 不经过 next-intl 中间件，改读 **`NEXT_LOCALE` cookie**（next-intl 每次页面请求都会写，同源 fetch 自动携带） |
| 通知文案 | `src/lib/notification-message.ts` | 落库存 `{"key","params"}`，渲染时按**读者**语言生成（老纯文本数据原样返回） |
| 校验消息 | `src/lib/validations.ts` | 每个 schema 是 `getXSchema(t)` 工厂，调用点传入当前语言 |
| 路由跳转 | `@/i18n/routing` 的 `Link`/`useRouter` | 用 `next/link` + 硬编码 `/admin/...` 会在 `/en` 下跳回中文站 |

## 三、两个校验脚本

### `npm run i18n:check` → `scripts/check-i18n.mjs`（静态，秒级）

| 规则 | 细节 |
|---|---|
| R1 词条对齐 | 把 `messages/zh.json` 与 `en.json` 深度展开成点分 key 集合，双向比对；缺一个键就报 `messages/en.json is missing: <key>` 并 **exit 1** |
| R2 键引用存在性 | 扫描 `src/**/*.{ts,tsx}`：先用三条正则找出「变量 → namespace」映射（`useTranslations/getTranslations/getApiT`，含 `{namespace: "..."}` 写法与无参形式），再匹配该变量调用的**字面量**键；候选键必须同时存在于两种语言，否则报 `unknown key … <- <文件>` |
| R3 硬编码中文 | 正则 `[\u4e00-\u9fff]` 逐行扫描，忽略以 `//`、`*`、`/*` 开头的行；命中的文件若不在白名单就报 `hardcoded CJK <文件>:<行>` |
| 非失败项 | 「not referenced statically」只打印，不影响退出码（这 111 个键多为动态拼接或历史遗留） |
| 扫描范围 | 仅 `src/`，不含 `crawler/`、`scripts/`、`messages/` 自身 |

**白名单（`CJK_ALLOWED`，5 个文件）**：`src/app/api-docs/page.tsx`（开发用页面，不参与 locale 路由）、
`src/app/layout.tsx`（中文兜底元数据）、`src/lib/auth.ts`（next-auth 字段标签，本站不渲染）、
`src/lib/crawler-ingest.ts`（写入 `CrawlLog` 的运维日志）、`src/lib/utils.ts`（`formatRelativeTime` 的中文分支，
已按 locale 参数正确切换）。

### `npm run i18n:check:runtime` → `scripts/check-i18n-runtime.mjs`（对运行中的服务发 HTTP）

默认目标 `CHECK_BASE=http://127.0.0.1:3103`：

```bash
npm run build && npx next start -p 3103
# 另一个终端：
npm run i18n:check:runtime
```

| 组 | 断言 |
|---|---|
| A. 无用户内容的英文页 | `/en/login`、`/en/register`、`/en/about`、`/en/help`、`/en/privacy`、`/en/contact` 必须 200，且去掉语言切换器自称「中文」后 **CJK 命中为 0** |
| B. 数据驱动的英文页 | `/en`、`/en/solutions`、`/en/questions`、`/en/software`、`/en/search` 必须 200，且出现指定英文标记、不出现指定中文界面文案 |
| C. 中文默认仍在 | `/login` 含「欢迎回来」、`/about` 含「关于我们」、`/solutions` 含「解决方案」 |

它捕捉的是静态检查看不到的泄漏：根 layout 继承的元数据、数据库驱动文案（站点描述）、页面整段 copy。

## 四、工作流

**新增一条文案**

1. 在 `messages/zh.json` 与 `messages/en.json` 的同一 namespace 下**同时**加同一个键。
2. 服务端用 `const t = await getTranslations("ns")`，客户端用 `const t = useTranslations("ns")`，不要硬编码中文。
3. 跑 `npm run i18n:check`（R2 会验证键名写对，R3 会抓漏改的中文）。

**从服务端组件改到客户端组件**：把 `getTranslations` 换成 `useTranslations`，注意后者不能 `await`。

**带插值的句子**：用 ICU 参数（如 `t("notFound", { entity: t("entity.article") })`），
避免拼接句子导致语序错误；带链接的句子用 `t.rich` 把 `<Link>` 嵌进译文（`/help` 页是范例）。

**新增语言**

1. 加 `messages/<locale>.json`（键集必须与 zh 完全一致）。
2. 在 `src/i18n/routing.ts` 的 `locales` 加代码；`src/i18n/request.ts` 会自动按文件名装载。
3. 检查 `scripts/check-i18n-runtime.mjs` 的断言清单，按需补充。
4. 更新本文与 [frontend.md](./frontend.md) 的 locale 表。

## 五、已知坑

| # | 现象 | 处置 |
|---|---|---|
| 1 | 检查脚本只认**字面量**键 | `t(someVar)`、模板串拼出的键不会被校验，改动这类代码要人工核对 |
| 2 | 行尾注释里的中文会误报 | 注释需整行以 `//`、`*`、`/*` 开头才被忽略 |
| 3 | `NEXT_LOCALE` cookie 决定 API 语言 | 用 `curl` 直接调接口时若不带该 cookie，返回的是中文（`getRequestLocale` 回落默认 locale） |
| 4 | 数据库文案只有一份 | `SiteConfig.siteDescription` 等只存中文，`/en` 回退到词条表翻译（首页 hero 与页脚） |
| 5 | 通知旧数据 | 结构化为 `{key,params}` 之前写入的纯文本通知会原样显示，不会翻译 |
| 6 | 后台页面很长 | `admin` 命名空间占 423 键，新增后台功能时优先复用既有子命名空间（`*Ui`）而不是新开 |
